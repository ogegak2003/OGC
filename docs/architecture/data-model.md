# Data model

PostgreSQL 18 via Prisma 7. Schema: `apps/api/prisma/schema.prisma`. Migrations:
`apps/api/prisma/migrations/` (forward-only, reviewed like code).

## Conventions

- Primary keys are UUIDs (`@db.Uuid`): UUIDv7 generated by the application for index
  locality; **session IDs are random v4** because they are embedded in refresh tokens.
- `snake_case` tables and columns; timestamps are `timestamptz(3)`.
- Secrets are never stored: passwords as Argon2id PHC strings, tokens as SHA-256 hex.
- Rules Prisma cannot express (CHECK constraints, triggers) live in migration SQL and are
  covered by `apps/api/test/database.test.ts`.

## Entity overview

```text
users ─┬─ 1:1 ─ profiles
       ├─ 1:N ─ credentials          (unique per user + type)
       ├─ 1:N ─ devices ── 1:N ── sessions
       ├─ 1:N ─ sessions             (also linked directly for "all sessions of a user")
       └─ 1:N ─ email_verification_tokens

users ─┬─ 1:N ─ contact_requests     (as sender / as recipient)
       ├─ 1:N ─ contacts             (as owner / as contact; one row per direction)
       ├─ 1:N ─ blocks               (as blocker / as blocked)
       ├─ 1:N ─ user_reports         (as reporter / as reported; SET NULL on delete)
       └─ 1:N ─ staff_roles

users ─┬─ 1:N ─ device_keys ── 1:N ── key_packages, mls_welcomes   (devices ── 1:N ── device_keys)
       └─ N:M ─ conversations (via conversation_participants)

conversations ─┬─ 1:N ─ messages ─┬─ 1:N ─ message_edits, message_reactions, message_hides
               │                  └─ 1:N ─ attachments
               ├─ 1:N ─ mls_commits (one per epoch)
               └─ 1:N ─ mls_welcomes
devices ── 1:1 ── push_tokens

audit_events                          (no foreign keys — outlives what it describes)
```

All child tables use `ON DELETE CASCADE` from `users`; `audit_events` keeps `user_id` as a
plain column so history survives account deletion.

## Tables

### `users`

| Column                     | Type            | Constraints                                                 |
| -------------------------- | --------------- | ----------------------------------------------------------- |
| `id`                       | uuid            | PK                                                          |
| `ogc_id`                   | varchar(12)     | unique; CHECK `^OGC[1-9][0-9]{8}$`; **immutable** (trigger) |
| `email`                    | varchar(254)    | unique; CHECK stored lower-case and trimmed                 |
| `email_verified_at`        | timestamptz     | nullable                                                    |
| `status`                   | `AccountStatus` | default `PENDING_VERIFICATION`                              |
| `created_at`, `updated_at` | timestamptz     |                                                             |

### `profiles`

`user_id` (PK, FK), `display_name` varchar(64) (CHECK not blank, **not unique**), `bio`
varchar(280), `avatar_key` (unique; CHECK `avatars/<uuid>.webp`), `profile_visibility`
(`CONTACTS` default), `discoverable` (default true), `contact_request_policy` (`EVERYONE`
default), timestamps.

### `credentials`

| Column               | Notes                                                   |
| -------------------- | ------------------------------------------------------- |
| `type`               | `CredentialType` (`PASSWORD`); unique with `user_id`    |
| `secret_hash`        | Argon2id PHC string                                     |
| `failed_login_count` | consecutive failures (CHECK ≥ 0); reset on success/lock |
| `locked_until`       | lockout end, nullable                                   |
| `last_used_at`       | last successful use                                     |

### `devices`

`id`, `user_id` (indexed), `platform` (`WEB`/`ANDROID`/`IOS`/`DESKTOP`), `name`
(client-supplied label, varchar(64)), `created_at`, `last_seen_at`.

### `sessions`

| Column                            | Notes                                                                              |
| --------------------------------- | ---------------------------------------------------------------------------------- |
| `id`                              | random UUIDv4 (embedded in the refresh token)                                      |
| `user_id`, `device_id`            | FKs, both indexed                                                                  |
| `access_token_hash`               | char(64), **unique** — the per-request lookup key                                  |
| `access_expires_at`               | 15 minutes after issue/refresh                                                     |
| `refresh_token_hash`              | char(64), replaced on every rotation                                               |
| `expires_at`                      | absolute session end (CHECK after `created_at`)                                    |
| `last_used_at`                    | written at most every 5 minutes                                                    |
| `revoked_at`, `revocation_reason` | set together (CHECK); reasons: `LOGOUT`, `REFRESH_TOKEN_REUSE`, `ACCOUNT_DISABLED` |

### `email_verification_tokens`

`token_hash` (unique), `expires_at` (CHECK after creation), `consumed_at` (single use;
issuing a new token consumes outstanding ones).

### `audit_events`

| Column                  | Notes                                                               |
| ----------------------- | ------------------------------------------------------------------- |
| `type`                  | `AuditEventType` enum (registration, login, sessions, verification) |
| `user_id`, `session_id` | plain UUIDs, nullable (unknown-account failures have none)          |
| `ip_address`            | `inet`; honours `TRUST_PROXY_HOPS`                                  |
| `user_agent`            | truncated to 256 characters                                         |
| `metadata`              | JSON with non-sensitive context only (e.g. failure reason)          |

Indexed by `(user_id, created_at)` and `(type, created_at)`. **Append-only**: a trigger
rejects `UPDATE` and `DELETE`.

### `contact_requests`

`sender_id`, `recipient_id` (FKs, cascade), `status` (`PENDING`/`ACCEPTED`/`DECLINED`/`CANCELLED`),
`created_at`, `responded_at`. CHECK not self; CHECK `responded_at` set exactly when not pending;
**partial unique index on the unordered pair where `status = 'PENDING'`**. Indexes
`(recipient_id, status, id)` and `(sender_id, status, id)` serve the request lists.

### `contacts`

`owner_id`, `contact_id` (FKs, cascade), `created_at`. Unique `(owner_id, contact_id)`; index
`(owner_id, id)` for pagination; CHECK not self. Written in pairs by the accept transaction.

### `blocks`

`blocker_id`, `blocked_id` (FKs, cascade), `created_at`. Unique pair; index `(blocker_id, id)` and
`(blocked_id)`; CHECK not self.

### `user_reports`

`reporter_id`, `reported_user_id` (FKs, **SET NULL** so reports survive account deletion),
`category` (enum), `description` varchar(1000), `status` (`OPEN`/`RESOLVED`/`DISMISSED`),
timestamps. Partial unique index: one OPEN report per reporter, reported user and category;
CHECK not self.

### `staff_roles`

`(user_id, role)` primary key; `role` is `MODERATOR` or `ADMIN`. Granted by operators only.

### Messaging (Phase 3)

Details and rationale: [messaging.md](messaging.md), [sync.md](sync.md),
[encryption.md](encryption.md).

| Table                       | Key columns and rules                                                                                                                                                                                                                                                                                    |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `device_keys`               | `id` (random v4, embedded in MLS credentials), `device_id`, `user_id`, `signature_public_key` (32 bytes, unique), `revoked_at`. Partial unique index: one active key per device                                                                                                                          |
| `key_packages`              | `device_key_id`, `ref` (hex, unique), `data` (≤ 4 KiB), `expires_at`, `claimed_at` (each package handed out once)                                                                                                                                                                                        |
| `conversations`             | `id` (random v4, = MLS group ID), `type` (`DIRECT`), `direct_key` (unique ordered pair, CHECK format/consistency), `version` (change counter), `mls_epoch`, `group_info`, `last_activity_at`                                                                                                             |
| `conversation_participants` | `(conversation_id, user_id)` PK, `last_read_seq`, `last_delivered_seq` (high-water marks). Trigger: DIRECT participants must be the pair in `direct_key`                                                                                                                                                 |
| `messages`                  | UUIDv7 `id`, `seq`/`version` (unique `(conversation, seq)`), `sender_id`, `sender_device_key_id`, `client_message_id` (unique per sender), `epoch`, `ciphertext` (≤ 64 KiB; NULL exactly when deleted), `reply_to_id` (composite FK: same conversation), `forwarded`, `revision`/`edited_at`, `withheld` |
| `message_edits`             | Edit metadata only: `(message_id, revision)` unique, editor device, time                                                                                                                                                                                                                                 |
| `message_reactions`         | `(message_id, user_id, reaction)` PK; CHECK reaction in the fixed set                                                                                                                                                                                                                                    |
| `message_hides`             | "Delete for me": `(user_id, message_id)` PK with a `version` for sync                                                                                                                                                                                                                                    |
| `mls_commits`               | `(conversation_id, epoch)` PK (one commit per epoch), `version`, `data`                                                                                                                                                                                                                                  |
| `mls_welcomes`              | Pending Welcome per target device key; unique `(device_key_id, conversation_id, epoch)`                                                                                                                                                                                                                  |
| `attachments`               | Random v4 `id`, `conversation_id`, `uploader_id`, `message_id` (NULL until sent), `kind`, `size`, `sha256` of the ciphertext, `storage_key` (CHECK `attachments/<uuid>.bin`)                                                                                                                             |
| `push_tokens`               | One per device (`device_id` PK); `(provider, token)` unique                                                                                                                                                                                                                                              |

New audit events: `DEVICE_KEY_REGISTERED`, `DEVICE_KEY_REVOKED`, `CONVERSATION_CREATED`,
`MESSAGE_DELETED_FOR_EVERYONE` (IDs only — never content).

assert there is **no drift** between the migrated database and `schema.prisma`.

## Planned evolution

- **Personal data retention:** a retention policy for `audit_events.ip_address`/`user_agent`
  (e.g. pseudonymise after 90 days) before launch.
- **Least-privilege roles:** separate migration and runtime database roles; the runtime
  role gets no `TRUNCATE`/DDL rights and no `UPDATE`/`DELETE` on `audit_events`.
- **E2E encryption:** implemented with MLS in Phase 3 (`device_keys`, `key_packages`,
  `mls_commits`, `mls_welcomes`); groups and encrypted channels (Phase 4) added conversation
  types and participant roles.
- **Local message retention:** per-conversation pruning of device-local history (Planned).
